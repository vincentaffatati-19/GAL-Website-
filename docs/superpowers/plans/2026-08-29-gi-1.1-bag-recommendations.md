# GI-1.1 Bag + Recommendation Audit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add durable Jerry’s Bag history/scenarios and a deterministic, reproducible recommendation audit chain while preserving the existing current bag and decision-snapshot tables.

**Architecture:** Extend `gal_bags`, `gal_bag_items`, and `gal_decision_snapshots` additively. Store historical bag/configuration changes and what-if scenarios in new tables. Freeze profile/bag snapshots for recommendation runs, store candidate items and score components, and prove commerce fields cannot alter deterministic ranking.

**Tech Stack:** PostgreSQL 17, Supabase migrations/RLS, pgTAP SQL, deterministic JavaScript scoring fixtures where required by existing guide logic.

**Spec:** `docs/superpowers/specs/2026-08-28-golfer-intelligence-data-model-v1.1-design.md`

## Global Constraints

- `gal_bags` + `gal_bag_items` remain authoritative for real current equipment.
- Scenarios never mutate actual bag state until explicit adoption.
- Product identity and configuration are separate.
- Partial equipment identity remains valid.
- Product Fit Score is separate from whole-bag Optimization Score.
- “Keep current” and “reconfigure current” are valid recommendation outcomes.
- Same frozen inputs + same data/model versions must produce the same ranking.
- Commerce economics never enter Fit Score/rank logic.
- Completed recommendation history is immutable.
