# GAL UX5 MID RC1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `GAL-UX5-MID-RC1`, reconciling the authenticated My GAL portal to the locked My GAL Intelligence Dashboard visual architecture while preserving existing governed equipment, profile, fitting, insight, entitlement, security, and truthfulness contracts.

**Architecture:** Keep the current TypeScript/Vite portal data clients and governed view-model logic. Replace RC-UX4 presentation with a dedicated UX5 shell and visual layer, reuse one bag-environment component across Today/My Bag, and turn Driver intelligence into a contextual panel/tab experience rather than a disconnected linear page. Missing or unsupported data renders honest learning/withheld states; the reference screenshot controls composition but not facts.

**Tech Stack:** TypeScript 7, Vite 8, Vitest 4, Supabase JS, semantic HTML, CSS, local repository-controlled image assets.

**Spec:** `docs/superpowers/specs/2026-09-04-gal-ux5-mid-locked-design.md`

## Global Constraints

- UX identifier is exactly `GAL-UX5-MID`; first review candidate is exactly `GAL-UX5-MID-RC1`.
- Read `GAL_UX_MANIFEST.json` and `GAL_UX_CURRENT.md` before changing UX code.
- Primary navigation remains exactly `Today | My Bag | Insights | Guides | Progress`; Golfer Profile remains separately accessible.
- Use the locked Option 7A Motion Arc / GAL Custom Hybrid brand assets; do not generate or substitute the GAL logo.
- Desktop composition follows the locked 1536×1024 visual reference; mobile is an intentional adaptation, not a scaled screenshot.
- Realistic golf/course/equipment imagery is required; crude hand-built golfer, club, bag, or course illustrations are rejected.
- Do not fabricate sample metrics, optimization states, yardage gains, valuations, recommendations, confidence, profile completeness, or real-world results.
- Preserve Tell GAL Once, governed evidence, RLS/browser safety, server-only service credentials, and existing data/security boundaries.
- Registered and subscriber experiences share components and analytical truth; subscriber capabilities remain additive.
- Production must not be changed or promoted without explicit user approval.
- Use TDD for every behavior change: demonstrate RED, implement minimal GREEN, then run the full portal test/build gate.
