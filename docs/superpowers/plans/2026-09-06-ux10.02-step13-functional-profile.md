# UX 10.02 Step 13 Functional Profile Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the approved UX10.02 profile prototypes into a real authenticated, governed golfer-profile flow backed by the existing GAL longitudinal profile architecture, with truthful connection/import states and complete staging verification.

**Architecture:** Keep the public GAL site static and add the authenticated profile surface under `portal/`. Browser code uses only the Supabase publishable key, resolves the authenticated golfer through `auth.users.id -> gal_users.auth_user_id -> gal_users.id`, and reads/writes only that golfer's `gal_profile_facts` through existing RLS. Direct user facts and imported measured facts remain atomic, sourced, scoped and quality-classified; no provider is shown as Connected without an approved live integration event. Insight-lifecycle mutations remain outside this profile implementation and continue to require the trusted server boundary defined by the portal longitudinal spec.

**Tech Stack:** Static HTML/CSS, ES modules, Node 22 built-in test runner, Supabase JS 2.115.0 pinned for browser runtime, PostgreSQL/Supabase RLS, headless Chromium for browser smoke verification.

**Spec:** `docs/superpowers/specs/2026-08-31-portal-longitudinal-integration-design.md`

## Global Constraints

- Preserve the six approved UX10.02 areas: You, Your Game, Your Swing, Your Miss, Where You Play, Connected Golf.
- Preserve locked Miss vocabulary: finish = Left/Straight/Right/Short/Long; shape = Hook/Pull/Straight/Push/Slice.
- Missing values remain absent/null; never manufacture sample facts.
- Preserve provenance classes: `MEASURED`, `OBSERVED`, `SELF_REPORTED`, `INFERRED_ESTIMATED`; never silently upgrade a user-reported fact to `MEASURED`.
- `gal_profile_facts` is the canonical profile fact store. Atomic fact uniqueness is `(user_id, fact_key, scope)`.
- Browser profile CRUD must rely on existing golfer-owned RLS and never accept another golfer's `user_id` as an editable field.
- Browser runtime may use only `SUPABASE_URL` and a publishable key. Never expose a service-role/secret key.
- A provider may display `CONNECTED` only when a governed live integration has established that state. Otherwise use truthful statuses such as `NOT_CONNECTED`, `PARTNERSHIP_REQUIRED`, `UNAVAILABLE`, or `IMPORT_AVAILABLE`.
- Toptracer/Topgolf remains partnership/API-required; Arccos-type and Garmin-type sources remain unavailable until an approved integration exists.
- Manual import is the functional Step 13 path for launch-monitor data where no approved live API exists.
- Profile coverage means profile areas started, not confidence, completeness or performance quality.
- The same profile contract must support registered users and subscribers; entitlements must not fork profile ownership or fact semantics.
- Staging verification uses `GAL Longitudinal Staging` only; never copy production golfer data into staging.
- Production promotion remains gated by the repository release policy requiring a `release/*` branch.

### Task 2: RLS-Safe Profile Store

**Files:**
- Create: `portal/profile-store.mjs`
- Test: `tests/profile-store.test.mjs`

**Interfaces:**
- Consumes: normalized rows from `buildProfileFactRows`.
- Produces: `createProfileStore(supabase)` with `getAuthenticatedContext()`, `loadProfileFacts()`, `saveFacts(rows)`, `deleteFacts(keys)`.
- `getAuthenticatedContext()` calls `supabase.auth.getUser()`, then selects the single active `gal_users` row matching the authenticated identity through RLS.
- `saveFacts(rows)` must overwrite `user_id` with the resolved GAL user id instead of trusting a caller-supplied id, and upsert with `onConflict: 'user_id,fact_key,scope'`.

- [ ] **Step 1: Write failing mock-client tests** proving unauthenticated access fails, authenticated identity is resolved, caller-supplied foreign `user_id` is discarded, own rows are selected, atomic upsert conflict keys are correct, and deletions are restricted to the resolved golfer.

- [ ] **Step 3: Implement the minimum store** using only browser-safe Auth/Data API calls.

- [ ] **Step 5: Commit** with `feat: add RLS-safe profile store`.
