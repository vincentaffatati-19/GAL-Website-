# GI-1.1 Guide Integration + Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Integrate the stable GI-1.1 backend contracts into the existing static GAL Buyer’s Guides one guide at a time, add registered-user persistence/known-fact reuse, and produce an immutable release candidate with complete regression evidence.

**Architecture:** Add a small shared browser-side GAL intelligence client rather than embedding Supabase/profile logic independently into every guide. Keep each guide’s deterministic scoring logic intact unless an explicitly versioned model change is approved. Migrate guides incrementally, validate known-fact reuse and recommendation parity after each conversion, then add CI/regression/release-manifest gates.

**Tech Stack:** Static HTML/CSS/vanilla JavaScript, Supabase JS client or existing REST-compatible browser access pattern selected during execution, Node built-in test runner for pure JS adapters, browser smoke testing, GitHub Actions/GitHub Pages.

**Spec:** `docs/superpowers/specs/2026-08-28-golfer-intelligence-data-model-v1.1-design.md`

## Global Constraints

- Preserve current locked Option 7 GAL Custom Hybrid branding.
- Existing guide scoring remains deterministic; AI does not rank products.
- Known current facts are reused; stale/uncertain facts are confirmed rather than blindly reused.
- Guest users can still use guides; registration unlocks persistence rather than better advice.
- Registered-user state is server-backed; local storage is not authoritative.
- Do not create guide-specific shadow profile keys.
- Fairway Woods & Hybrids must pass explicit hang/runtime regression before every RC.
- Update/verify golfer and customer shared contracts together when affected.
- Production promotion requires immutable RC + explicit user approval.
