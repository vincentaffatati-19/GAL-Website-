# GI-1.1 Connected Services + Privacy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add provider-neutral connected-data contracts and enforce privacy/consent lineage so imported golfer data can improve personalization without leaking into prohibited commercial uses.

**Architecture:** Use a system-governed provider catalog plus golfer-owned connection metadata and trusted sync-run records. Normalize provider values into canonical GAL facts with explicit source/use restrictions. Keep provider credentials outside normal application-readable tables and prove raw golfer operational data remains unavailable to customer roles.

**Tech Stack:** PostgreSQL 17, Supabase migrations/RLS, pgTAP, synthetic provider fixtures, server-side adapter JavaScript.

**Spec:** `docs/superpowers/specs/2026-08-28-golfer-intelligence-data-model-v1.1-design.md`

## Global Constraints

- External authorization is explicit and provider scope is minimized.
- GAL never stores another app’s user password.
- Imported values map to canonical GAL semantics and retain provenance.
- Provider authority is data-type specific.
- Both golfer consent and provider terms must permit downstream use.
- Provider restrictions propagate to derived/commercial eligibility.
- Revocation stops future sync and invalidates/removes active credentials.
- Customer systems never query raw individual golfer data.
- Sensitive fitting accommodations are excluded from commercial analytics.
- Baseline commercial cohort threshold is 50; more granular cohorts may require larger thresholds.

- [ ] **Step 1: Write failing tests**
