# GI-1.1 Longitudinal Intelligence State Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Normalize behavioral events, make `gal_intelligence_state` rebuildable/versioned, and add milestone intelligence snapshots plus deduplicated material insights.

**Architecture:** Keep `gal_buyer_events` as the single event stream, add catalog/version/session/journey metadata, and derive current intelligence through deterministic state-generation functions/services. Durable facts, bag state, recommendation records, and events remain sources of truth; `gal_intelligence_state` remains a cache.

**Tech Stack:** PostgreSQL 17, Supabase migrations/RLS, pgTAP, JavaScript state-builder fixtures where needed.

**Spec:** `docs/superpowers/specs/2026-08-28-golfer-intelligence-data-model-v1.1-design.md`

## Global Constraints

- Behavior is evidence, not automatically truth.
- `gal_buyer_events` remains canonical; do not create a second behavior table.
- Material events are append-only; invalidation records error without rewriting history.
- `gal_intelligence_state` is client read-only and rebuildable.
- Unknown/inferred/declared/imported values remain distinguishable in state.
- Low-value events do not trigger full recomputation.
- Customer portal cannot access raw state/events.
